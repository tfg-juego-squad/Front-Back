Función 03 · Constructor de Entregas 09 / 16

◆ Nueva Entrega — un examen en 5 pasos.

El profesor configura puntuación, tiempo y tipo (formulario clásico, avanzado con minijuego o diálogo narrativo). El sistema valida todo automáticamente antes de publicar.

1

Datos básicos

Título, descripción y puntuación máxima objetivo.

2

Elegir tipo

3 pestañas: Formulario · Avanzado (con minijuego) · Diálogo.

3

Añadir preguntas dinámicas

TEST o DESARROLLO. Puntos y tiempo por pregunta. Se renumeran solas.

4

Validación automática

Solo 1 pestaña activa · TEST con 1 correcta · suma de puntos = objetivo.

5

Publicar

POST a /tfg/prueba → disponible en el aula seleccionada.

Conclusiones · Aprendizajes 15 / 16

Lo que nos llevamos del TFG.

◆ Pensar como producto

No basta con que funcione: cada pantalla debe ser usable, coherente y entendible al primer vistazo. La UX importa tanto como el código.

◆ Arquitectura primero

Decidir los Autoloads, las carpetas y la API antes de meter código nos ahorró semanas de refactor. Modular = escalable.

◆ Frontend ≠ pintar

Routing, estado, validación, conexión a API, animaciones, físicas… el frontend es ingeniería de pleno derecho.

Próximos pasos

Más niveles, sistema de inventario, ranking global persistido en backend, sonidos y música original, build empaquetada para Windows y Web.
